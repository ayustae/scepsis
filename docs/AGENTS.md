## Rules and conventions

- Do not mix reference documentation with guides with system designs in the same document. All things are useful but serve different purposes and have different audiences.
- The documentation should be comprehensive, but easy to follow. This applies both, to the directory structure and the files themselves.
- Structure this folder with subfolders as needed, each one serving a particular purpose as you see fit. Expect to find different kinds of documents about different elements. Categorising documents per element, per kind, or per expected audience is up to you.
- Expect that this classification may evolve as additional documents are added. When the final structure stabilises, these conventions will change and the final one will be fixed here.
